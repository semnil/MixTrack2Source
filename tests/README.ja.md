# 音声の回帰テスト

[English](README.md)

このテストは、人工的に生成した音声をプラグインと実際の libobs に通す。
一時的な設定と画面に表示しない描画環境を作り、OBS アプリの起動、マイクやスピーカーの使用は行わない。

Xcode Command Line Tools と Python 3.9 以降がある macOS で、リポジトリのルートから実行する。

```sh
mkdir -p work
bash tests/prepare-audio-deps.sh work/audio-deps
python3 tests/run-audio-mix.py --deps work/audio-deps --results work/audio-results --sanitize --check-mutex
```

準備処理は OBS 32.1.0、その版に対応するソースのヘッダー、SIMDe 0.8.2 を取得する。
結果の保存先は実行ごとに新しいディレクトリにする。入力ファイルのハッシュ、終了状態、
音声サンプル、時刻、通知の到着時刻、JSON の判定結果を保存する。

パルスの個数・振幅・元入力の時刻に加え、別々に計算した PCM (音声サンプル列) の位置を照合する。
直列接続では、各段の遅延が 1,024 サンプルであることを、1 サンプルの測定許容差で検査する。
循環に含まれるインスタンスは無音を出し、循環を解消すると音声が戻ることを検査する。
一覧の競合テストでは、インスタンス一覧のロックを保持し、音声コールバックが待たずに
時刻付きの無音を出し続けることを検査する。列挙のテストでは、OBS がソース一覧のロックを
保持している間に入力トラックを変更する。
モニターのみの検査では、ソースの音声通知と最終トラックの音声を照合する。通常出力への
切り替え、3 インスタンスの接続、出力の分岐も含む。存在しないモニター機器を指定して
スピーカー再生を防ぐ。実際の機器によるモニター再生は検査しない。
`late-source` は片方の入力を 20 ms 遅らせ、OBS のバッファを 64 ms に固定して、
入力時刻を厳密に照合する。他の条件では既定の動的バッファを使う。
これはテスト用の設定であり、プラグインの設定は変えない。

通知の到着差は別に報告する。接続動作の回帰テストでは、その上限を合格条件にしない。
Issue #7 で未達の 16 ms という目標を判定するときは、次を実行する。

```sh
python3 tests/check-notification.py work/audio-results --limit-ms 16
```

このコマンドは目標を超えると失敗する。接続動作の回帰テストの合格は、Issue #7 の解決を意味しない。
`--source PATH` で別の版のプラグインを同じテストに掛けられる。`--cases` で条件を選び、
`--rate` で 44.1、48、96 kHz を選ぶ (既定は 48 kHz)。

開発者は音声の接続処理を変えるときに、このテストを実行する。GitHub Actions の
`Audio regression` ワークフローは、`src`、`tests`、ワークフロー自身が変わる PR と
デフォルトブランチへの push で、macOS 上のテストを実行する。
